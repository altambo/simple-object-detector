# SimpleObjectDetector

A serverless web app that runs YOLOv8 object detection on images. You upload an image (or paste an image URL) in a static web page; AWS Lambda queues the job, a container Lambda runs the model, and the page polls until the annotated image is ready.

## Architecture

```
Browser ──POST /──▶ API Gateway ──▶ GetImageUrlFunction ──▶ S3 (uploads) + DynamoDB + SQS
   │                                                                         │
   │                                                                         ▼
   │                                                          ProcessImageFunction (YOLOv8 container)
   │                                                                         │
   └──GET /{imageId}──▶ API Gateway ──▶ SODCheckJobStatus ◀── DynamoDB ◀─────┘
                                                              (status + presigned result URL)
```

### Frontend (`frontend/`)
- **`index.html`**: single-page UI with upload, URL input and status display.
- **`main.js`**: vanilla JavaScript that submits the image (base64 or URL), polls job status every 10 seconds, and shows the result.
- **`config.js`**: generated by `deploy.sh` with the deployed API URL. It is git-ignored; see `config.example.js` for its shape.

### Backend (AWS, defined in `template.yaml`)
- **HTTP API Gateway (`SODGatewayApi`)**: routes requests, with CORS and request throttling.
- **`GetImageUrlFunction`** (`backend-lambda/get_image_url.py`): accepts a request, stores uploaded images in S3, records the job in DynamoDB and enqueues it on SQS.
- **SQS queue (`SODQueue`)**: decouples ingestion from processing.
- **`ProcessImageFunction`** (`backend-container/`): x86_64 container Lambda running `yolov8m.onnx` with Ultralytics. It downloads the image, runs detection, uploads the annotated result and writes a 15-minute presigned URL to DynamoDB.
- **`SODCheckJobStatus`** (`backend-lambda/check_image_status.py`): returns a job's status from DynamoDB.
- **DynamoDB table (`SODJobStatusTable`)**: job status records.
- **S3 buckets**: a public bucket hosts the static website; a separate private bucket holds uploads and results (expired after 7 days).

All resource names include the environment name, so `dev` and `prod` stacks can coexist in one account.

## Prerequisites

1. **AWS CLI v2**, configured with credentials (`aws configure`): [install guide](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)
2. **AWS SAM CLI**: [install guide](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html)
3. **Docker**: SAM builds the Lambda packages and the container image with it (`sam build --use-container`).
4. **Git LFS**: the model weights (`backend-container/yolov8m.onnx`) are stored with [Git LFS](https://git-lfs.com). Install it before cloning, or run this after cloning:
   ```bash
   git lfs install
   git lfs pull
   ```

## Deploy

```bash
./deploy.sh dev    # default
./deploy.sh prod
```

The script:
1. Clears the local `.aws-sam/` build cache.
2. Validates and builds the SAM template.
3. Deletes the stack first if it is stuck in `ROLLBACK_COMPLETE` / `ROLLBACK_FAILED`.
4. Runs `sam deploy` to stack `SimpleObjectDetector-<env>` in `us-east-1` (edit `REGION` in `deploy.sh` to change it).
5. Writes `frontend/config.js` from the stack outputs.
6. Uploads `index.html`, `main.js` and `config.js` to the website bucket.

When it finishes, it prints the website URL and API endpoint. Open the index URL in a browser.

## Local development

To run the Lambda handlers locally, copy `.env.example` to `.env`, fill in the names of deployed resources, and install the dev dependencies:

```bash
pip install -r requirements-dev.txt
```

## Security notes

- The repository contains no credentials. Deployment uses your local AWS CLI credentials, and the Lambdas use IAM roles scoped to the stack's resources.
- `frontend/config.js`, `.env` and `samconfig.toml` are git-ignored because they contain deployment-specific values.
- **The API is unauthenticated.** Anyone with the URL can submit images, and each job runs a 3 GB Lambda for up to 4 minutes. API Gateway throttling limits the rate, but set up an [AWS Budgets](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html) alert, and add authentication if you deploy this publicly for long.
- Image URLs submitted by users are only fetched over `http`/`https` from public IP addresses, with a 10 MB size limit.
